## 5. Code Quality Coaching (Non-Scoring)

- **Inline styles in React pages**: [LoginPage.tsx](BuckeyeMarketplaceFrontend/src/pages/LoginPage.tsx), [AdminDashboardPage.tsx](BuckeyeMarketplaceFrontend/src/pages/AdminDashboardPage.tsx), and other pages define large `styles` objects inline using `CSSProperties`. Consider CSS Modules or a shared design-token approach (the project already has `DESIGN_TOKENS.md`) to reduce duplication and improve consistency.

- **Missing SUBMISSION.md**: The rubric submission guidelines request a top-level `SUBMISSION.md` with test credentials, security practices summary, and AI usage link. While this is not a scoring item, including it helps graders evaluate faster. The security practices are documented in `ai-usage-by-date.md` but would benefit from a centralized summary.

- **AllowAnonymous on order placement**: [OrdersController.cs](BuckeyeMarketplaceBackend/Controllers/OrdersController.cs#L37) — the `PlaceOrder` endpoint uses `[AllowAnonymous]` to support guest checkout, which is a valid design choice. However, consider rate-limiting anonymous order endpoints to prevent abuse in production.

- **Error swallowing in catch blocks**: Several frontend pages (e.g., [LoginPage.tsx](BuckeyeMarketplaceFrontend/src/pages/LoginPage.tsx#L112)) have empty `catch` blocks with comments that errors surface via context. This pattern works but could confuse future maintainers. Consider a named pattern like `// Error handled by AuthContext` or a shared convention.

- **PlaceOrderRequest model-binding risk**: The integration test `GuestCheckout_RejectsUnexpectedUserAndTotalFields` verifies that extra fields like `userId` and `total` are rejected via model validation. This is excellent defensive design — keep this practice going.
